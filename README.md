# WinKeepAwake · 防息屏守护

一个 Windows 原生的防屏幕超时锁定 / 防息屏工具：现代 GUI + 系统托盘后台常驻，
用「鼠标零位移注入 + 电源管理声明」让系统保持唤醒，可配置指定时间后自动停止。

单文件 exe，无需安装、无需外部资源，双击即用。

## 它解决什么问题

在会议室演示、挂机下载、长时间阅读等场景下，系统会因「一段时间无输入」自动息屏或锁屏。
WinKeepAwake 通过周期性地向系统注入微小的输入事件并声明电源请求，让「最后输入时间」持续刷新，
从而阻止息屏与锁定。窗口可最小化到托盘，后台静默运行，前台几乎无感。

## 三层防御

1. **鼠标注入（默认，主力）**：`SendInput` 发送 `MOUSEEVENTF_MOVE`。
   - `零位移（无感）`：`dx=0, dy=0`，光标视觉完全不动，不触发 hover、不干扰拖拽。
   - `±1px 抖动`：兼容性兜底，用于极少数会过滤零位移的严格检测环境。
   - 运行时自检：注入后立即复查 `GetLastInputInfo` 是否被刷新，零位移未被接受则**自动降级**为 ±1px。
2. **电源管理声明（主力）**：`SetThreadExecutionState(ES_CONTINUOUS | ES_SYSTEM_REQUIRED | ES_DISPLAY_REQUIRED)`，
   每 60s 刷新一次。直接命令系统层计时器不启动，不依赖检测方是否识别注入痕迹。
3. **键盘扫描层（可选，默认关闭）**：注入 `F13` 虚拟键按下 + 释放。
   选 F13 是因为它几乎不被任何应用绑定、也不像 Ctrl/Shift 那样有与真实按键时序重叠而误触快捷键的风险。
   仅在鼠标 + 电源声明不足以应对的极端环境手动开启。

> 说明：用户态无法伪造内核的 `LLMHF_INJECTED` / `LLKHF_INJECTED` 注入标志位。
> 若某检测手段专门识别「注入位」而非「最后输入时间」，本工具无法绕过——这是诚实的固有边界。

## 功能特性

- **现代 GUI**：eframe/egui 深色主题，圆角卡片布局，实时状态灯、空闲计时、累计注入次数、运行日志。
- **系统托盘后台常驻**：关闭窗口默认最小化到托盘（可关闭该行为）；托盘左键单击/双击切换窗口显隐，右键菜单提供「显示/隐藏、暂停/恢复、退出」。
- **保活逻辑独立于界面**：核心循环跑在独立 worker 线程，即使窗口隐藏、界面不再高频重绘，防息屏依然持续。
- **定时自动停止**：可配置 5–480 分钟后自动停止并释放电源声明，界面实时显示剩余时间。
- **空闲阈值可调**：10–300 秒。
- **中文字体自动适配**：运行时加载系统自带中文字体（微软雅黑等）作为字形回退，无需随附字体文件。
- **图标程序化生成**：托盘/窗口图标由代码绘制 RGBA，无外部图片依赖。

## 构建与运行

需要 Rust 工具链（建议 1.98+，`edition 2021`），目标平台 Windows 10/11。

```bash
# 开发运行（带控制台，便于看 panic）
cargo run

# 发布构建：单文件、无控制台窗口的独立 exe
cargo build --release
# 产物：target/release/WinKeepAwake.exe（约 5 MB）

# 质量门禁
cargo test          # 21 项单元/逻辑测试
cargo clippy --all-targets
```

Release 通过 `#![cfg_attr(not(debug_assertions), windows_subsystem = "windows")]` 隐藏控制台窗口，
并启用 LTO + `strip` + `panic = "abort"`，产出体积最小的独立 exe。

## 架构

```
src/
├── main.rs     eframe App：界面渲染 + 收集配置 + 托盘初始化 + 窗口关闭拦截（UI 与 logic 分离）
├── worker.rs   后台保活线程：命令通道、空闲检测、注入调度、定时停止、快照发布
├── jitter.rs   纯 Win32 封装：SendInput 注入、GetLastInputInfo 空闲、SetThreadExecutionState、窗口显隐
├── icon.rs     程序化生成 RGBA 图标（无外部资源）
└── font.rs     运行时加载中文字体作为 egui 字形回退
```

- **线程模型**：`worker` 线程跑保活循环（1s tick），通过 `std::sync::mpsc` 接收 GUI 下发的 `Command`，
  通过 `Arc<Mutex<Snapshot>>` 向界面回发只读快照。
- **窗口显隐**：走原生 Win32 `ShowWindow`，绕开 eframe `ViewportCommand::Visible` 在部分版本「隐藏后无法再显示」的边界问题。
  托盘回调只传递 `HWND` 的 `isize` 原始值（`HWND` 本身非 `Send`），在回调内同线程重建。
- **可测试性**：`worker` 支持注入 `TestHooks`（覆盖空闲读数与注入返回值）和可配置 tick，使核心逻辑可在毫秒级做确定性单元测试；
  真实「空闲是否归零」的端到端效果依赖系统输入时序，交由集成验证而非单元测试断言。

## 使用建议

- 日常挂机：保持默认「零位移 + 电源声明」，键盘层关闭，即为最无感组合。
- 遇到会过滤零位移的严格检测：切到「±1px 抖动」，或临时开启键盘层。
- 需要到点自动收工：开启「定时自动停止」并设定时长。

## 许可与免责

本工具仅用于在自有设备上防止意外的息屏/锁定。请在遵守所在单位安全策略与相关条款的前提下使用。
