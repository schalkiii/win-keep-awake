# WinKeepAwake · 防息屏守护

一个 Windows 原生的防息屏 / 防锁定工具：现代 GUI + 系统托盘后台常驻，**双工作模式**——
「防息屏」（注入 + 电源声明，屏幕保持常亮）与「息屏防睡」（到点正常关屏但系统保持满速唤醒），
可配置定时自动停止，托盘右键支持一键重启。

单文件 exe，无需安装、无需外部资源，双击即用。exe 图标与版本信息（VERSIONINFO）在构建期
由同一份绘制代码生成并嵌入 PE 资源段，任务栏/资源管理器里显示专属图标。

## 它解决什么问题

两类场景：

1. **会议室演示 / 挂机下载 / 长时间阅读**：系统因「一段时间无输入」自动息屏或锁屏。
   「防息屏」模式通过周期性注入微小的输入事件并声明电源请求，让「最后输入时间」持续刷新，阻止息屏与锁定。
2. **锁屏过夜但机器要继续干活**（挂机 agent、计划任务、远程编译）：
   需要「屏幕可以关，但系统不睡眠、不待机、不进低功耗转换」。
   「息屏防睡」模式声明 `ES_SYSTEM_REQUIRED`（不含 DISPLAY），让关屏超时正常生效而系统保持唤醒。

> **「息屏防睡」的重要边界（本机实测）**：开发机（ThinkBook 14 G8 IAL，Intel Arc 130T）
> 2026-11 有三次夜间锁屏挂死，全部发生在「屏幕已关 + 已有系统保活请求在场
> （PowerToys Awake 持 SYSTEM 声明）」的环境下——即**系统级保活声明并不能可靠阻止该机的关屏路径挂死**，
> 根因嫌疑是核显驱动的关屏/运行时低功耗转换（12× 0x141 WATCHDOG）。
> 在显卡驱动修复前，过夜请用「防息屏」模式（屏幕常亮，唯一零死亡记录的配置）；
> 「息屏防睡」仅建议白天短测使用。UI 内也有同样的警告。

## 三层防御（防息屏模式）

1. **鼠标注入（默认，主力）**：`SendInput` 发送 `MOUSEEVENTF_MOVE`。
   - `零位移（无感）`：`dx=0, dy=0`，光标视觉完全不动，不触发 hover、不干扰拖拽。
   - `±1px 抖动`：兼容性兜底，用于极少数会过滤零位移的严格检测环境。
   - 运行时自检：注入后立即复查 `GetLastInputInfo` 是否被刷新，零位移未被接受则**自动降级**为 ±1px。
2. **电源管理声明（主力）**：`SetThreadExecutionState(ES_CONTINUOUS | ES_SYSTEM_REQUIRED | ES_DISPLAY_REQUIRED)`，
   每 60s 刷新一次。直接命令系统层计时器不启动，不依赖检测方是否识别注入痕迹。
3. **键盘扫描层（可选，默认关闭）**：注入 `F13` 虚拟键按下 + 释放。
   选 F13 是因为它几乎不被任何应用绑定、也不像 Ctrl/Shift 那样有与真实按键时序重叠而误触快捷键的风险。
   仅在鼠标 + 电源声明不足以应对的极端环境手动开启。

> 说明：用户态无法伪造内核的 `LLMHF_INJECTED` / `LLKHF_INJECTED` 注入标志位。
> 若某检测手段专门识别「注入位」而非「最后输入时间」，本工具无法绕过——这是诚实的固有边界。

## 息屏防睡模式的工作原理与安全设计

- **电源声明**：`ES_CONTINUOUS | ES_SYSTEM_REQUIRED | ES_AWAYMODE_REQUIRED`（无 `ES_DISPLAY_REQUIRED`），
  与本机 kuku 签到任务 keep-awake 包装相同的组合。
- **不注入任何输入**：注入会刷新显示空闲计时、阻止关屏，与该模式目的直接冲突。
- **电源计划动态写入**：进入模式时临时把「关闭显示超时」（VIDEOIDLE）与「控制台锁定显示关闭超时」
  （VIDEOCONLOCK，隐藏设置）的 AC/DC 值都设为息屏等待分钟数（`powercfg -set*index`，普通权限即可），
  **暂停 / 切回常亮 / 定时停止 / 退出时立即恢复原值**。
  安全不变量：**允许关屏 ⟺ 本工具正在保护**——工具不在运行的世界永远回到「从不关屏」基线。
- **漂移防护**：本机电源计划受域 GPO 周期管理（实测手工写入的值数小时内会被改回默认），
  模式运行期间每 5 分钟校验一次生效值，被外部改动自动重新应用并记日志。
- **崩溃边界（诚实声明）**：进程被强杀（`TerminateProcess`）时来不及恢复电源计划，
  关屏超时会残留——下次手动恢复，或重启即净。GUI 的电源写入失败时会安全降级为「屏幕常亮 + 系统唤醒」并显示原因。

## 功能特性

- **现代 GUI**：eframe/egui 深色扁平设置面板——头部为真实渲染图标（随模式切换）+ 状态指示，
  分段式模式选择器（一次点击切换）、行式设置（左标签右控件）、小节分区（模式设置 / 定时自动停止 / 通用）、
  4px 细进度条（空闲逼近阈值 / 关屏倒计时 / 定时停止剩余）、实验性模式橙色警示横幅（长文收进悬停提示）、
  等宽字体分级彩色日志（信息/警告/错误三色，占满剩余高度）、动态窗口标题（`WinKeepAwake · 模式 · 状态`）。
  模式设置区固定高度，切换模式时下方段落零跳动。
- **双工作模式**：防息屏（常亮注入保活）/ 息屏防睡（到点关屏、系统不休眠），模式切换即时生效。
- **系统托盘后台常驻**：关闭窗口默认最小化到托盘（可关闭该行为）；托盘左键单击/双击切换窗口显隐（菜单只由右键唤起），右键菜单提供「显示/隐藏、暂停/恢复、重启工具、退出」。**托盘图标随模式切换**：咖啡杯（青，防息屏）/ 月牙星（靛蓝，息屏防睡），提示文字带运行状态。
- **托盘一键重启**：拉起新实例后退出；息屏防睡生效中会用 `--screen-off-guard <mins>` 启动参数交接状态，
  新实例自动恢复该模式（GUI 首帧从快照同步模式显示，中间约一秒声明空窗）。新实例启动失败则保持旧实例运行。
- **保活逻辑独立于界面**：核心循环跑在独立 worker 线程，即使窗口隐藏、界面不再高频重绘，防息屏依然持续。
- **定时自动停止**：可配置 5–480 分钟后自动停止并释放电源声明（息屏防睡下同时恢复电源计划），界面实时显示剩余时间与总进度；可选“到点立即锁屏”（`LockWorkStation`，普通权限）。
- **空闲阈值可调**：10–300 秒；息屏等待 1–60 分钟。
- **中文字体自动适配**：运行时加载系统自带中文字体（微软雅黑等）作为字形回退，无需随附字体文件。
- **图标程序化生成**：SDF + 2× 超采样抗锯齿，16–256px 七档尺寸干净渲染；无外部图片依赖。
  `build.rs` 在构建期用同一份代码组装多尺寸 .ico 并嵌入 exe（含 VERSIONINFO），
  托盘/窗口图标运行时直接生成。`WinKeepAwake.exe --dump-icons <dir>` 可导出两种模式图标的 BMP 供视觉验收。

## 构建与运行

需要 Rust 工具链（建议 1.98+，`edition 2021`），目标平台 Windows 10/11。

```bash
# 开发运行（带控制台，便于看 panic）
cargo run

# 发布构建：单文件、无控制台窗口的独立 exe（图标/版本信息在此时嵌入）
cargo build --release
# 产物：target/release/WinKeepAwake.exe（约 5 MB）
# 注意：构建期图标嵌入需要 Windows SDK 的 rc.exe（winresource）。

# 质量门禁
cargo test          # 38 项单元/逻辑测试（+1 项真机 powercfg 往返，默认 ignored）
cargo clippy --all-targets
```

Release 通过 `#![cfg_attr(not(debug_assertions), windows_subsystem = "windows")]` 隐藏控制台窗口，
并启用 LTO + `strip` + `panic = "abort"`，产出体积最小的独立 exe。

## 架构

```
src/
├── main.rs     eframe App：界面渲染 + 收集配置 + 托盘初始化（含重启/退出的电源恢复）+ 窗口关闭拦截 + 托盘图标/动态标题
├── worker.rs   后台保活线程：命令通道、空闲检测、注入调度、模式切换、电源计划启停与漂移校验、定时停止、分级日志、快照发布
├── jitter.rs   纯 Win32 封装：SendInput 注入、GetLastInputInfo 空闲、SetThreadExecutionState（常亮/仅系统两档）、窗口显隐
├── power.rs    powercfg 封装：关屏超时读写/备份恢复/漂移校验（UTF-16 兼容解码，普通权限）
├── icon.rs     程序化生成 RGBA 图标：双设计（咖啡/月牙）+ SDF + 超采样（无外部资源）
├── font.rs     运行时加载中文字体作为 egui 字形回退
└── build.rs    构建期：复用 icon.rs 生成 16–256px 多尺寸 .ico，经 winresource 嵌入 exe（图标 + VERSIONINFO）
```

- **线程模型**：`worker` 线程跑保活循环（1s tick），通过 `std::sync::mpsc` 接收 GUI 下发的 `Command`，
  通过 `Arc<Mutex<Snapshot>>` 向界面回发只读快照。
- **窗口显隐**：走原生 Win32 `ShowWindow`，绕开 eframe `ViewportCommand::Visible` 在部分版本「隐藏后无法再显示」的边界问题。
  托盘回调只传递 `HWND` 的 `isize` 原始值（`HWND` 本身非 `Send`），在回调内同线程重建。
- **退出路径的电源恢复**：暂停/切模式/定时停止由 worker 恢复；托盘退出与重启在事件回调里显式调用
  `power::end_display_off()`（`std::process::exit` 不经过 eframe 的 `on_exit`）；窗口关闭与 eframe 正常退出
  由 `on_exit` 兜底。唯一无法恢复的路径是强杀/崩溃（已在 UI 与 README 声明）。
- **可测试性**：`worker` 支持注入 `TestHooks`（覆盖空闲读数、注入返回值与电源启停/校验）和可配置 tick，
  使核心逻辑可在毫秒级做确定性单元测试；`power` 的 powercfg 输出解析对 UTF-16LE/UTF-8/本地代码页兼容并有样例测试；
  真实 powercfg 往返有 `#[ignore]` 真机测试（`cargo test -- --ignored`）。
  真实「空闲是否归零」「关屏是否发生」属系统时序，交由集成验证而非单元测试断言。

## 使用建议

- 日常挂机：保持默认「零位移 + 电源声明」，键盘层关闭，即为最无感组合。
- 遇到会过滤零位移的严格检测：切到「±1px 抖动」，或临时开启键盘层。
- 需要到点自动收工：开启「定时自动停止」并设定时长。
- **过夜挂机（本开发机）**：用「防息屏」模式（屏幕常亮）。「息屏防睡」在显卡驱动修复前仅白天短测。
- 工具卡住/更新后：托盘右键「重启工具」，息屏防睡状态会自动交接。
